## 从文件开始

这个博客没有数据库，也没有复杂的后台。每一篇文章就是一个 Markdown 文件，文章目录和展示信息写在一个 JavaScript 配置里。

这样的结构很朴素，但它有一个很实际的优点：内容和页面分开了。改文章的时候不必碰布局，改布局的时候也不会影响正文。

## 一个清晰的发布动作

静态网站最适合把发布变成一个简单动作：

```text
写 Markdown -> 更新 config.js -> 提交 Git -> 自动部署
```

没有服务器状态需要同步，没有后台账号需要维护，备份也只是代码仓库本身。

## 轻量不等于简陋

我更愿意把轻量理解成“每一层都知道自己负责什么”。HTML 负责结构，CSS 负责视觉，JavaScript 负责路由和数据读取，Markdown 负责内容。

当工具边界清楚时，网站反而更容易长久维护。它不一定拥有最多功能，但每个功能都能被解释。

## 留给未来的空间

以后可以加上标签筛选、RSS、搜索，甚至把 Markdown 构建成静态 HTML。但这些都应该是内容真的需要之后再发生的事。

先让文字被好好读完，再考虑下一件事。
